# Changelog

One entry per merged PR that changes what a skill does, or how the framework is installed or checked. Newest first. A rename or a removal names what replaced it.

## Unreleased (v0)

- `shape-spec`'s interviewer reads no code itself: subagents read it and bring back their findings, so the code never buries the round's format in its context. A subagent that returns while a round waits on the user sends nothing new; when its facts change a question already asked, the round is sent again in the same format.
- `shape-spec`'s grill and `shape-architecture`'s questions format a round as `❓ **Q1** - **<title>**: <question>`, then `➡️ <recommendation>` on its own line, with `---` between questions; the message holds the round only. The `Open:` line of branches still open is gone.
- `shape-architecture` stops when its argument is not a spec issue, and gives `/shape-spec <idea>` as the next command: it never writes a spec's stories, promises, or `done_when` itself. `shape-spec`'s grill sends each round as a message that ends the turn, answered in the user's own words, instead of a form of buttons; the question tool stays for a round of one question between named options, and `harness.md` names the exception. Each round opens with the branches still open, and an answer that opens a branch gets its follow-up in the next round. `shape-architecture`'s questions write "leave it to the builder" in each one.
- Behavior is settled in the spec, the shape in the architecture ([ADR 0027](docs/adr/0027-behavior-is-settled-in-the-spec-the-shape-in-the-architecture.md), amending ADR 0024). `shape-spec`'s grill gains the branch What the code already does: a subagent lists the behaviors the feature collides with in the code, such as a cascade delete, a copied value, or a total over every record, and each one a user would see becomes a product question. `shape-architecture` no longer asks a product question: it names the decision the spec lacks, leaves open the shape decisions that hang off it, and hands over `/shape-spec <issue>` instead of `/ship`. `shape-spec` takes a spec issue with an open product decision, grills it, and edits the spec in place.
- `create-app-driver` gets to a working driver faster on an unknown repo. Before any install it runs a read-only preflight that stops at the first failure with its fix: the pinned runtime version against the one in PATH, the package manager of the lockfile, the container daemon, Launch's ports, the driver's tools; the generated skill keeps it as its Preflight section; it never changes the machine, and runs a runtime the PATH lacks through a per-run selector such as `nvm exec`, never by changing the default. It starts from the repo's own documented dev command, and proves the driver with one instance driven serially, one retry after a fix, then a stop with the blocker. It writes no Demo section any more: the first task whose coverage requires a demo adds `record-demo` to the driver, as the driver's own change that `ship`'s frame routes; the same holds for a Profile line and for base and head side by side, and `investigate` adds the Profile line before a capture ([ADR 0019](docs/adr/0019-the-spec-sets-the-bar-and-a-task-builds-the-proof-it-lacks.md)). `Profile` is written only when the repo has a cheap profiling command, side by side is answered from the code and proven by the first task that needs it, and the control CLI starts with `launch`, `doctor`, `drive`, and `stop`. Evidence files name the entry point they used. `drivers.md` gains a `Windows hosts` section (a detached launch through `Start-Process` with every handle redirected, `taskkill` by PID, `cygpath -w` and MSYS argument rewriting, PowerShell's read-only variables, native processes and ports, the Store `python3`, a timeout on every wait), and notes that a dev server that locks its checkout needs a worktree per instance. `features/README.md` opens with the baseline every recipe shares: never drive an instance the run did not start, restore the seed after a change, what a screen and a command proof hold, and a skipped entry point never verified through another path.
- New skill `/shape-architecture`: the architecture shaped apart from the intent, when you want a say in it ([ADR 0024](docs/adr/0024-the-architecture-is-shaped-apart-from-the-intent.md)). On a spec issue, it sketches two shapes in code, screens them, and puts the decisions they carry to you in rounds, each with a recommendation and the option to leave it to the builder. The decisions you make go into the spec's new Technical decisions section, numbered `D1`, with the base commit they were grounded on; the sketches are saved to `sketches/<spec>/` in the project folder. `shape-spec` looks for four signals before its hand over (a one-way door, two viable shapes, a change of owner or boundary, an ADR the spec comes close to) and offers the skill on one; its Decisions section now keeps the product decisions only. `ship` builds within the technical decisions: its frame names them, it grounds a stale one again, its two sketches differ only on what is left open, and a decision the code contradicts stops the task before code, or leaves the PR `needs-human` when found during the build; the user's answer goes back into the spec under a new id that quotes it. `shape-architecture` never reshapes a spec a `ship` task is building. `verify-pr`'s `spec` lane checks the diff against each decision, and a breach of a decision the spec holds is a `should`, whether or not Deviations names it. The design method (data shape, grounding, two sketches, screen, red flags) moves from `ship/references/design.md` to `constitution/references/architecture.md`, and `sketch.md` moves beside it, so both skills follow one method. The trackers gain the operation Edit an issue; in a tracker file written from a template before, the first skill that needs an operation the template now answers copies its heading.
- New skill `/maintain-app-driver` replaces the maintain mode of `create-app-driver` ([ADR 0025](docs/adr/0025-the-feature-map-grows-by-maintenance.md), amending ADR 0021). It checks every feature file against the source with one read-only subagent each, drives every mapped feature live, triages drift, harness gaps, and product regressions, and maps at most five features the map lacks per pass, those a `learn-from-mistakes` row named first. `create-app-driver` maps 3 to 5 features and no longer writes the entry-point check, so a large app is not mapped whole in the first run; a feature file lists its entry points by hand again, and `coverage.md` counts those. `create-app-driver` also: reaches each state a journey needs through the user's path first, and writes a seed for a state no user path reaches, beside the driver, so private unless the driver already lives in the repo, without asking; installs its tools outside the repo's manifest and lockfile; prefers a browser control CLI to a shipped Playwright script, and never records a step by a snapshot ref; lists the setup steps a stand-in did as unverified; and mocks only at a boundary the code already has. `learn-from-mistakes` routes a feature map gap to `/maintain-app-driver`, with the row as its argument. A task that touches a feature with no file writes it (`coverage.md`). A schedule the user sets up outside the framework counts as the user launching ([ADR 0026](docs/adr/0026-a-schedule-is-the-users-own.md), amending ADR 0014), and rule 11 of the constitution says so; the framework still ships none.
- The framework works before `/setup-repo` ([ADR 0023](docs/adr/0023-the-framework-works-before-setup-repo.md)). When the project folder has no `issue-tracker.md`, the first skill that needs an issue writes the default tracker: private markdown files in `~/.agents/projects/<project>/issues/`, numbered across the repo so `/ship 7` names one issue, written from the reworked `local.md` template, whose shared variant now lives at `.scratch/issues/`. `shape-spec` and `learn-from-mistakes` no longer stop without a tracker file, and no skill lists unfiled issues in its reply any more. A PR's state is the new State line of its body (`in progress`, `ready`, or `needs-human`), beside the Verdict line; the labels `ready` and `needs-human` mirror it where they exist, and no skill creates them. `babysit-pr`, `ship`, `ship-queue`, and `resume-task` read and write the line. `setup-repo` treats a default tracker as a part still to offer, and moves its open issues when the user picks another tracker. `ship`'s frame names a missing merge guard and goes on.
- The repo and the plugin are renamed `skillstack`, replacing `software-ai-skills-framework`: install with `/plugin install skillstack --marketplace Ilian-Allaf/skillstack`, and the skills answer to `/skillstack:<skill>`. GitHub redirects the old URL. The project folder becomes `~/.agents/projects/ilian-allaf__skillstack/`, since its name comes from `origin`.
- `docs/history/` is removed ([ADR 0022](docs/adr/0022-the-first-design-notes-leave-the-repo.md)): the first design notes bound nothing, and git keeps them. Every file of the repo is in English, except `resources/`.
- `evals/` is removed: it held only the format of verdict cases, and no case. `verify-pr`'s calibration no longer moves a fixed example into it; the example stays in `calibration.md` until its lesson becomes a rule. `knowledge/` is renamed `resources/`; `tools/check_refs.py` lists the rename under `MOVED`, so a living doc that names `knowledge/` fails, and a dated doc keeps its old path while the new one exists.
- `skills/README.md` is removed; `skills/GRAPH.md` replaces it ([ADR 0021](docs/adr/0021-the-skill-graph-is-the-executed-map.md), superseding ADR 0013). `tools/check_refs.py` checks the graph's skill table: R006 now fails on a skill with no row, and the new R012 fails when a row's Runs or Run by disagrees with the skills' `calls:` frontmatter. Links from a file at the top of `skills/` are now checked (R001), and a removed file is allowed only in the dated docs.
- A heavy visual change is specified by a target, still or in motion ([ADR 0020](docs/adr/0020-a-heavy-visual-change-is-specified-by-a-target.md), proposed). When a story adds a screen, redesigns one, or builds a page whose look is the point, `shape-spec` says so first and adds two decisions: the design mode (`follow`, `extend`, or `break away`), recommended from the design system a subagent reads in the code, and the pick among prototypes. `investigate`'s prototype mode does the work: your references first, or five to eight it proposes; motion references read frame by frame into an effect list; three variants from the repo's real components, at desktop and phone width, recorded when they move; feedback made specific. The spec gains Visual targets (`V1`): captures of stills, recordings of motion with their effect list, the measured checks, and the bans; no score. `ship`'s `feature` playbook builds the stills, then motion, each closed by the target loop of the new `references/visual-loop.md`: passes scored by a race of fresh critics, kept or reverted past their spread, logged one row per pass, ten passes per kind; a measured check still failing then means `needs-human`. New `constitution/references/ui.md` holds the criteria, the widths, the measured checks, the motion rules, and the generic defaults to drop. `verify-pr`'s `live` lane captures and records each target itself; only a failed measured check, a missing or mistimed effect, or a ban a command detects is a finding, `spec` counts a component the design mode excludes as unasked, and `standards` reads `ui.md` for notes only. `check_evidence.py` fails when a visual target has no case. `harness.md` gains the reference library, recording, and frame cutting, and a critic row. A heavy visual task that reaches `ship` with no target is proposed `/shape-spec`.
- An ADR records only what the code cannot say: `shape-spec` first asks whether an architecture, a type, a check, or a test can hold the decision, writes no ADR when the code says all of it, and keeps only the why and the alternatives rejected otherwise. `encode-lessons-in-structure` now applies before a decision or a rule is written in a doc, so the verifier's `standards` lane flags an ADR the code already says. `CODING_STANDARDS.md` points to that rule instead of copying it.
- A task builds the proof it lacks ([ADR 0019](docs/adr/0019-the-spec-sets-the-bar-and-a-task-builds-the-proof-it-lacks.md), parts 2 and 3 of 3; the ADR is now accepted). `ship`'s frame copies the spec's journeys and promises as cases by their ids, aims each case at the highest proof its kind allows (a certainty level for a journey, formal check, generated inputs, then examples for a property), and builds what is missing first: a driver for a touched surface, a formal check for a promise the user stated in a hard zone, a repair of a check stale on the base. A driver built in a task is followed cold by a fresh subagent; a private check's base version is saved for the verifier. `check_evidence.py` fails when a spec id has no case. Rule 11 stops for access only the user can give. A `medium` or `high` task without a spec drafts its own journeys and promises. `verify-pr`'s brief carries the spec issue: `live` drives its journeys and promises by their ids, a story or promise missing from the coverage table is graded as any missing case, `spec` reads its Out of scope, and `breakage` judges each formal check made or repaired in the task against its base version. `create-app-driver`, `create-formal-verification`, and `maintain-formal-verification` leave `babysit-pr` to the task's stack when a task runs them first.
- The spec sets the verification bar ([ADR 0019](docs/adr/0019-the-spec-sets-the-bar-and-a-task-builds-the-proof-it-lacks.md), part 1 of 3). `shape-spec`'s grill gains a verification branch: a journey per story, promises with their harm, and what cannot be verified, drafted by the agent and confirmed with a yes. It looks up the drivers and formal checks of the area, and writes the access for a surface without a driver to `access/<app>.md` in the project folder. The spec template gains journeys, Promises, and Not verifiable, numbered so the evidence names each one.

- New skill `/show-me`: shows the current topic visually, with the smallest pseudocode, call tree, component tree, file tree, Mermaid diagram, diff, or focused HTML artifact that makes the point clear, instead of a wall of prose. You launch it; no other skill calls it.

- Verdicts cover the tested base and head commits, with rules and replay environment recorded ([ADR 0018](docs/adr/0018-a-verdict-covers-the-tested-base-and-head.md)). A changed base or head requires fresh proof and verification, even after a conflict-free rebase with the same patch id. Babysitting and stacks use this rule; the local evidence checker requires full base and head SHAs and rejects older records that contain only a patch id. Per-run records stay in PR comments and existing artifacts.

- A formal check guards every task that touches its code ([ADR 0017](docs/adr/0017-a-formal-check-guards-every-task-that-touches-its-code.md)): every file a `prove-<area>` covers is a hard zone, so such a task is never `low` and the verifier runs `breakage`; `frame` marks a check stale on the base as Not verified and opens an issue for `/maintain-formal-verification`; a builder whose change alters covered code updates the check and lists the update in Proof; the verifier breaks the guarded code once, and a missed break or a check left stale is a FAIL. Staleness compares each covered file with the content id the check records, so a squash merge or a fresh clone leaves an updated check in sync. A model is shown able to fail by describing the code's break in the model; a private harness runs in the worktree under check. A shared check runs in the repo's CI. `proof.md` says where formal checks live and how to find the ones a diff touches, `create-formal-verification` names the exact paths it writes, and `formal.md` says how a private harness that must be built with the code runs in a scratch worktree without being committed.
- New skills `/create-formal-verification` and `/maintain-formal-verification` replace the formal mode of `create-app-driver`. The first proves one property over every case in a stated scope, shows it can fail, and checks the `prove-<area>` it writes with a fresh subagent on a scratch break; it no longer needs a driver first. The second brings a check back in line after changes that skipped it: it runs the check before any edit, sorts every change to covered code, updates the model from the code, breaks it again after a pass, and gives each check one outcome (`in sync`, `updated`, `bug`, `blocked`). Their shared rules, the shape of `prove-<area>`, and the definition of a stale check live in `constitution/references/formal.md`; the glossary gains sync commit and stale.
- `SCOPE.md` no longer requires the same failure seen twice before a new skill enters: a new skill faces the same bar as any change, and its PR says why no existing skill can absorb it.
- The repo's working files (tracker file, glossary, ADRs, coding standards, rule table, drivers) live in the project folder, `~/.agents/projects/<project>/`, outside the repo, so the framework imposes no file on the team. `setup-repo` asks, file by file, private or shared; a shared file stays in the repo and the project folder routes to it. Every skill reads the project folder; the linter holds it (P006). A repo prepared before keeps its files: rerun `/setup-repo` to write the routes ([ADR 0016](docs/adr/0016-the-working-files-live-outside-the-repo.md)).
- First-use corrections: `ship` tries verification before implementation, audits recorded activity, and checks a local evidence index with a tested script; the comment hunter proposes patches with one retry for an invalid report. `verify-pr` records independent findings before reading prior diagnostics and retries blocked lanes only after setup changes. `learn-from-mistakes` reconstructs activity before trusting summaries. These procedures still need validation in a new real session.
- A PR now carries its issue: `ship` claims an issue task before it starts, so no other session takes it, and its PR says `Closes #<n>` (or `Part of #<n>` for an earlier unit of a stack), so the issue closes when the user merges. The tracker files gain the operation "Link a PR to the issue it delivers".
- Coherence audit fixed (27 findings), mostly with pstack's own rules: a missing driver is not a pass; a stop before the PR still opens it, `needs-human`; `babysit-pr` requests a missing verdict, removes a stale `ready`, and lets each `ship-queue` owner babysit its own PR (stack rules in `babysit-pr/references/stack.md`); rule 12 fixes on the way only what blocks the goal; every PR a skill opens gets a verdict and `babysit-pr` (rule 2); `pause-task` works without a branch and carries the decision log; `clean-worktrees` asks before untracked files and keeps paused tasks; ADR 0015 supersedes ADR 0012: principle ids in the PR, plain words in the decision log; the map and the one-task diagram follow the skills. A second audit (25 findings) fixed: the verifier keeps another family when one exists; queue owners are exempt from the stack lock, push after each attempt, and a stuck one ends as a `needs-human` PR; a FAIL during babysit has its route; pause handles a `ready` PR, a queue, and `shape-spec`'s docs branch; `ship` diagnoses an unreproducible bug and goes on or stops, and proposes `/shape-spec` for open decisions; a user-launched `/verify-pr` counts; a bounded check replaces the watcher where there is none; spec user stories become cases; one list of hard zones in `proof.md`. A third audit (20 findings) fixed: a stop says the call, a default, and what the user could say instead, and the user's answer in their own words restarts it (pstack's way; `/resume-task <PR>`); `ship-queue` resumes from its note, starts a stacked task once the one below has its PR, and keeps its owner brief in `references/owner-brief.md`; the bug fix only reproduces before the frame; a spec has its `done_when`; docs PRs and a colleague's PR can be verified; `gh label create` no longer overwrites labels.
- Principles are read one at a time: the constitution's Reading a principle says to read the full form of each principle you apply, never a whole group, and to cite only what you read in the session; `ship`'s design reads the principles its sketch relies on, and `verify-pr`'s standards lane those the PR cites or the diff calls for. W002 warns when a principle's full form passes 500 words.
- New skill `/recall-context`: a brief of where things stand on a topic, from past sessions and the repo's record. New user guide `docs/guide.md`: what to put in a prompt, prompts to copy per kind of work, the costly mistakes; R011 checks that each command it names is a skill.
- `create-app-driver` grows the driver into a small control CLI when the drive outgrows a script: composable commands, `--dry-run`, `--help`, JSON output, errors that say what to do, one command for the environment. New skill `/clean-worktrees` removes the worktrees of finished tasks and asks before any uncommitted work is lost.
- Faster review: `babysit-pr` pushes once per round and babysits a stack from its lowest PR, one babysitter per stack, keeping the stack's shape; `constitution/references/writing.md` sets how PR bodies, commits, replies, and docs are written; a PR's Why opens with who notices the change and what the next maintainer inherits.
- New skills: `/test-skill-change` runs the old and the new version of a skill on the same task, blind, judged on neutral labels, and recommends; `/sharpen-prompt` rewrites a prompt to ask for deeper work; `/say-it-plainly` restates the last reply in plain words.
- New skill `/ship-queue`: a list of independent tasks becomes as many PRs, one `ship` owner per task, each with its own verifier, watched by its side effects, stopped before every merge. New `ship` playbook `hillclimb`: one metric pushed to a target, one measured attempt at a time. `harness.md` gains Model per role, within one subscription. The constitution gains the coordinator role.
- New skills: `/pause-task` stops a task at a safe point with a resume note in a `wip:` commit (and on the PR), also on its own when the context or the usage limit runs low; `/resume-task` carries a stopped task on without redoing it; `/catch-me-up` reports what changed with its screenshots and videos, and every call waiting on you, or as a short video.
- A launched task runs to a ready PR without a go (ADR 0014, superseding ADR 0002): `ship` shows its frame and goes on, and stops only for a one-way door, a product call, evidence against the request, or a dead end. Constitution rules 11 to 13: launching is the go; what serves the goal is fixed on the way, in its own PR when outside the diff; a wrong skill is fixed or reported, never worked around. Rule 7: a plateau changes the approach, and `done_when` is never relaxed. Still no cron or scheduled run.
- `SCOPE.md` no longer requires an observed failure before a skill changes: a change fits the accepted ADRs and its PR says why it is worth it.
- `ship` designs with a method (`ship/references/design.md`): every feature and every change that crosses a function boundary is designed; the builder grounds in the history of the current shape, writes two sketches by the rules of `sketch.md`, screens them, and writes a design note in the PR's new Design section (`design-note.md`); a one-way door, or a user who asks at the go, sees the design before any code; the build follows the sketch, and six tells say when to scrap it.
- Principles reorganized: `principles.md` stays the one-line index, and every id has its full form in `constitution/references/principles/<id>.md`, with a test, the sign it was skipped, and an example when it shapes code. R010 checks that the index and the folder match. Ids renamed to say what they do: `foundational-thinking` is now `design-the-data-first`, `boundary-discipline` is now `validate-at-the-boundary`, `type-system-discipline` is now `make-illegal-states-unrepresentable`, `laziness-protocol` is now `make-the-smallest-change`, `tight-loop` is now `build-a-tight-loop`. New: `redesign-from-first-principles`, `design-for-the-consumer`. The TypeScript rules gain examples.
- The arena is removed from `parallel.md`: the builder sketches twice itself. The feature playbook names the bolt-on it rejected and checks every consumer of an improved primitive; `verify-pr`'s standards lane checks the shape against the red flags, the principles, and the design note. The README shows how to steer the agent with principle names.
- Every list of the skills is checked: `plugin.json` lists exactly the skills (R007), the README links each one (R008), and `choose-skill` names each one as a command (R009).

Every skill carries `agents/openai.yaml`, so Codex keeps it for the user to launch too; the linter checks both harnesses (F017, F018). `setup-repo` installs the merge guard as `harness.md` describes, instead of an `install.py` that was never built.
